## What it is
- A Python tool from Microsoft that converts files to clean Markdown. It handles PDF, Word, Excel, PowerPoint, HTML, CSV and JSON, and optionally images (OCR or captions through an LLM) and audio (transcription).
- It runs as a CLI (`markitdown file.pdf`), as a Python library, or as an optional MCP server (`markitdown-mcp`).
- It runs locally and has no daemon.

## Feasibility on our server
| Check | Result |
|---|---|
| Licence | MIT, so free and fine for our use. |
| Cost | Zero tokens and zero money for the conversion itself. The only paid parts are optional: image captions and audio transcription need an LLM or API key, and I would leave those off. |
| Token saving | Agents read compact Markdown instead of raw PDF or Office files. |
| Install | `pip install 'markitdown[pdf,docx,xlsx,pptx]'` in its own virtualenv, with a wrapper script at `programs/bin/`. Agents call it through the shell, so it works for every Lab agent without a Claude Code skill. The MCP server is optional and not needed. |
| Security (Perseus) | Treat input files as untrusted data. Run it on files only, never on arbitrary URLs. Leave the MCP server off, because it has no authentication. Pin the version and install only from the official PyPI package. |
| Size and upkeep | Small (hundreds of MB at most with the extras), with no service to run. |

## Why Khoj and AnythingLLM did not stay
The Lab records show only that both were removed on your instruction (MIC-212, MIC-233). I found no written reason. Both were heavy: Khoj used 6.9 GB plus a Postgres instance and a web server on port 42110, and AnythingLLM ran as a Docker container on port 3001. MarkItDown is the opposite: a stateless converter, with no database, no port and nothing running in the background. It adds no new memory app and no search engine, so it overlaps with neither.
