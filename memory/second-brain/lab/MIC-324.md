## Request

1. Files can be moved by drag and drop in the file explorer on all devices (desktop mouse, phone and tablet touch).
2. Folders can be moved by drag and drop on all devices, with their contents.
3. The same behaviour works on desktop, phone and tablet.

Context: the attached screenshot shows the Second Brain file explorer tree (memory, scripts, wiki > inbox, Screenshots, README.md and so on). It looks like the Obsidian-style explorer in the Second Brain web app. Related earlier task: MIC-283 (folder delete progress in the file explorer).

What to do: add drag and drop move to the explorer tree.
- Dragging a file or folder onto a folder moves it there. Dropping on the root area moves it to the root.
- Highlight the target folder while dragging.
- Use pointer events or a touch-friendly drag library, so it also works on touch screens. Native HTML5 drag and drop is not enough on mobile. A long-press should start the drag without breaking scrolling.
- Block invalid drops: a folder into itself or into one of its own children, and moves that would overwrite a file with the same name. Show a clear English message for these.
- Use the existing move or rename API, or add a server endpoint that moves inside the vault. Keep the path safe and inside the vault.
- Refresh the tree after a move and keep open folders open.
- Keep the UI English-only. Do not change other explorer behaviour.

How to check: test on a desktop viewport and a mobile viewport with touch emulation. Move a file into a folder, move a folder with files inside, and try the invalid drops. Confirm on disk that nothing is lost. Run the build and the tests.
