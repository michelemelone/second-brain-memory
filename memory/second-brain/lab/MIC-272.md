## Request

Project: Second Brain (app at memory.beedme.online). Related: MIC-268 (Import History moved to right sidebar tab), MIC-240 (persistent import history), MIC-269. Screenshot attached by the owner (uploads/da598fd5-be33-4037-b532-77404c1d831d/original.png) shows the Import & Staging page with the right sidebar.

Three fixes:
1. Right sidebar: when the user opens Import (Import & Staging), the right panel must open on the Import History tab, shown first and visible. Remove or hide the other tab icons (link, arrow, tag, outline, comment) that do nothing in this view. If any of them is useful in other views, show it only there and give each remaining icon a tooltip that explains what it does. Do not leave the panel empty.
2. Import History entries must be clickable. Clicking an entry shows what was done: for each file, the source name, the target folder, the status, and the path of every wiki or memory file created. Each created file must be a link that opens it in the file explorer or viewer. The current entry only shows 'Target: wiki, 1 file: Screenshots/Screenshot ....png, 1 imported', which does not say where the file went.
3. Image import: the owner uploads an image and asks to turn it into Markdown. Today it only stores the image again, unchanged, and makes no Markdown file. Fix it so that importing an image creates a .md note next to the image. The note must embed the image and contain an AI-generated description, any text found in the image (OCR) as Markdown, and a short title and tags. Reuse the existing model and fallback settings. The history entry must list this .md file and link to it. If the AI step fails, show a clear error and do not report it as imported.

How to check: build passes. Import a screenshot from the UI and confirm that (a) History is the visible first tab, (b) the entry opens its details, (c) a new .md with the description exists in the wiki and opens from the link. Test with screenshots of desktop and phone widths. UI text must be English only. Keep raw data separate: Gantry must never read the Second Brain. Deploy and restart the app safely when done.

**Tests and build**

**1. Right sidebar**
- On Import & Staging the right panel opens by itself, showing only the Import History tab. The other icons are hidden there.
- On other views the icons stay, and each tooltip now explains what it does.

**2. Clickable history entries**
- Clicking an entry expands it. For each file it shows the source, target folder, status, any error, and every created file as a link that opens the file in the viewer.
- Entries saved before this change have no per-file data. They show the old summary plus a note saying so.

**3. Image import**
- Images now default to "Convert to Markdown". The server asks the AI for a JSON answer with title, tags, description and text found in the image.
- It writes `<image>.md` next to the image, with front matter, the embedded image, a Description section and a "Text in the image" section when there is text.
- Models come from the "import" agent in Settings (primary, then fallbacks), skipping disabled engines. The defaults are claude sonnet, then antigravity gemini-3.8-flash-medium.
- If every model fails, the upload returns an error ("nothing was imported" plus each reason). Nothing is stored, and the history entry shows the file as Failed.
- Switching conversion off keeps only the image.

**Assumptions**
- Only Claude and Antigravity are used for images. OpenCode and Codex are skipped because their CLI image support isn't wired in.
- `agy -p --model` is a guess at the CLI syntax.
- The AI step runs before the write lock, so a slow model doesn't block other writes. The timeout is 3 minutes per model.

How to check: after the restart, open Import & Staging and import a screenshot. History should be the only right tab, and the entry should expand to show the image and the `.md` as links that open. Then check the same on a phone width.
