## Request

Live report (2026-11-17, owner, screenshots from memory.beedme.online): the left panel shows "Memory operations unavailable: login required" with a Retry button, and Settings & Agents shows Claude, Antigravity, OpenCode and Codex all as "NOT INSTALLED". Both are wrong: bigMike runs on this same machine and all four CLIs are installed and working.

ROOT CAUSE 1 - doubled API prefix (memory operations unavailable: login required)
- second-brain-app/server/src/app.ts, delegateToMemory (line ~93): const url = new URL(`${bigmikeUrl}/api${req.path}`).
- Inside app.get("/api/memory/repo") req.path is already "/api/memory/repo", so bigMike receives /api/api/memory/repo.
- bigMike's auth (personal-assistant/programs/server/src/auth.ts, memory exemption near lines 58-95) exempts only paths under /memory (it is mounted at /api), so the doubled path is a normal API path. delegateToMemory forwards the browser's cf-access-jwt-assertion, so the Access check passes and the request then fails the bigmike_session check -> 401 {"error":"login required"}, exactly the text in the UI. Without the JWT bigMike answers 401 {"error":"authentication required"}.
- Reproduced by curl: [http://192.168.12.200:3738/api/api/memory/repo](http://192.168.12.200:3738/api/api/memory/repo) -> 401, while [http://192.168.12.200:3738/api/memory/repo](http://192.168.12.200:3738/api/memory/repo) -> 200.
- Fix: forward the path exactly once (req.originalUrl already holds "/api/memory/..." plus the query string; or strip one leading "/api"), do not send browser cookies, keep the current query handling and the rule that only cache-control/etag/retry-after go back.
- Tests: a regression test for every delegated route (/api/memory/repo, /ask, /sync, /wiki, /wiki-agent, /schedules) that stubs bigMike and asserts method, exact upstream URL and query; plus a test that bigMike's 401 body is relayed unchanged.
- Related tasks: MIC-79 (the memory auth exemption), MIC-129, MIC-132.

ROOT CAUSE 2 - engines falsely NOT INSTALLED
- ~/.config/systemd/user/second-brain.service (tracked copy: second-brain-app/deploy/second-brain.service) sets no Environment=PATH. The service runs with systemd's default PATH (/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin), which does not contain /home/beedme/.local/bin (verified from /proc/2119/environ).
- The binaries are there and work: /home/beedme/.local/bin/claude -> Claude Code 2.1.326; /home/beedme/.local/bin/agy -> 1.5.10 (engine "antigravity"); /home/beedme/.local/bin/opencode -> 1.19.0; /home/beedme/.local/bin/codex -> 0.162.1.
- server/src/accounts.ts readStatus() runs execFile(bin, ["--version"]) and maps ENOENT to installed:false with "X is not installed on this machine."
- Fix both layers: (a) add Environment=PATH=/home/beedme/.local/bin:/usr/local/bin:/usr/bin:/bin to deploy/second-brain.service and to ~/.config/systemd/user/second-brain.service, daemon-reload and restart second-brain.service; (b) make Accounts resolve each CLI robustly (configured bin, then ~/.local/bin/<bin>, then PATH) and report the resolved path in the detail; never say "not installed" when the file exists. Keep the existing sign-in flow working.
- Verify: GET /api/engines/{claude,antigravity,opencode,codex}/status returns installed:true with the versions above, and the Settings & Agents panel no longer shows NOT INSTALLED after a reload.
