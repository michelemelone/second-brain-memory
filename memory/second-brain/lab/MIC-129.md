## 1. Why "login required"

The message is produced in one place, `personal-assistant/programs/server/src/auth.ts` (lines 79 and 92).

| Fact | Evidence |
|---|---|
| bigMike requires a bigMike session cookie for every `/api/*` path **except** `/api/memory/*` | `auth.ts` line 91: `if (!isMemoryPath(req.path) && !sessionOk) → 401 "login required"` |
| `/api/memory/*` is let through without a session in two cases: a call from this machine, or a call through the tunnel with a valid Cloudflare Access token | `auth.ts` lines 72–76 and 90–94. This was added in commit `dd2ccb2` (2026-11-17 11:28), "Memory API: let the Second Brain app reach /api/memory/* without a bigMike session" |
| Second Brain's server forwards `/api/memory/{repo,ask,sync,wiki,wiki-agent,schedules}` to bigMike at `http://127.0.0.1:3738`, passing only the `cf-access-jwt-assertion` header and no cookie | `second-brain-app/server/src/app.ts` lines 75–130 |
| The "Settings & Agents" view calls `GET /api/memory/repo` and `PUT /api/memory/wiki-agent`. These are the same calls as the memory operations | `web/src/SettingsPanel.tsx`, `web/src/api.ts` |

Because the Settings view and the memory operations share the same forwarding path, they fail together. A request that reaches bigMike as a memory path from the machine itself cannot return "login required". So one of these two suspects must be true:

| # | Suspect | Why it fits | Evidence |
|---|---|---|---|
| A | **A stale process.** The Second Brain server was started on 2026-11-16 at 23:10 (pid 1731769). Its `dist` was rebuilt on 2026-11-17 at 11:31, which includes the question box (`acc14a3`) and the Settings panel (`b22fb7c`). The running server was never restarted. | The static web files are read from disk, so the new Settings view shows up. The old server code in memory then forwards the calls. | `ps` start times and the `dist/server/main.js` timestamp |
| B | **The call reaches bigMike as "not local".** This happens if `BIGMIKE_URL` points at `bigmike.beedme.online` instead of `127.0.0.1:3738`, or if `memory.beedme.online` is proxied straight to bigMike (3738) instead of the Second Brain (3739). | A call through the tunnel carries Cloudflare headers, so `viaTunnel` is true and `localMemory` is false. A non-memory path such as `/api/tree` would also get "login required". | `auth.ts` lines 70–76 |

A weaker third possibility is bigMike itself. Its running process (pid 2888190) started on 2026-11-17 at 14:00, after `dd2ccb2` was committed. I cannot tell whether that build already included the commit, because `dist/auth.js` was rebuilt at 16:51.

**How to tell them apart.** Run these from the server:
- `curl -s -w ' %{http_code}\n' http://127.0.0.1:3738/api/memory/repo`. A JSON status means bigMike is fine, so the cause is A or B.
- The same call to `http://192.168.12.200:3739/api/memory/repo`. A 401 "authentication required" there is expected, since the Second Brain checks Cloudflare Access itself.
- `curl -s -o /dev/null -w '%{http_code}\n' http://192.168.12.200:3739/api/tree` should print 401, and the body of `/api/memory/repo` should come from the Second Brain.

I did not run these calls.
