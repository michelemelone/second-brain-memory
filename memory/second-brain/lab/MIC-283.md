# MIC-283: Second Brain: show live 'Deleting… N files' progress when deleting a folder in the file explorer

- Project: Second Brain
- Status: done
- Priority: medium
- Agent: Pegasus

- Updated: 2026-11-18

## Request

Problem: in the Second Brain file explorer (memory.beedme.online), clicking Delete in the 'Delete wiki/inbox/Screenshots' confirmation dialog looks like the app has frozen. There is no feedback while the folder is being removed (see the attached screenshot, original.png, in /home/beedme/data/workspace/personal-assistant/data/uploads/80b996d7-9c51-4c7d-ad6c-1ca08e5e814e/).

What to do:
1. Find out why the UI seems frozen. The likely causes are a slow synchronous delete, a git commit, or a reindex on the server, with no immediate UI response.
2. As soon as Delete is pressed, give clear feedback. Close or replace the confirm dialog with an in-progress state: 'Deleting… N / total files' with a counter that updates as it runs. Disable the buttons while it runs. Add a spinner or progress bar. Show a short success message at the end, and a clear error if it fails.
3. Count the files in the folder first, so the total is known. If the backend deletes everything in one call, make it report progress. Use streaming, polling a job status, or deleting file by file in batches, whichever is simplest and reliable. If real progress is not feasible, show an indeterminate 'Deleting…' state with the total file count, and explain why in the final report.
4. Keep the existing behaviour: the folder is still committed to git so history keeps it. Nothing else should be lost. The explorer tree must refresh when the deletion finishes. Check single-file delete and the right-click context menu as well.
5. All UI text must be in English.
6. Verify for real. Delete a test folder with many files, take screenshots of the dialog, the progress state and the final state, and confirm the files are gone and the git commit exists. Run the project's build and tests. Commit, push, and restart the app safely if needed so the change goes live.
7. In the final report, tell the owner (in Italian) whether live progress was possible and what was done.

Related: MIC-238 (file explorer dropdown/context menu fixes), MIC-242 (file explorer delete fix).

## Last report of the agent

**MIC-283 è fatto, ma non l'ho verificato nel browser: nessuno screenshot e nessuna cancellazione di prova su una cartella vera.** Il progresso live era fattibile e l'ho implementato.

**Perché sembrava bloccata.** Il server faceva tutto in una sola richiesta: scansione della cartella, cancellazione, `git add/commit` e poi `fetch` e `push`. Il push sulla rete è la parte lenta, e fino alla fine la UI non riceveva nulla.

**Cosa ho fatto.**
- **Server:** `DELETE /api/entry?stream=1` risponde con una riga JSON per ogni passo. Conta prima i file, li cancella uno a uno ("N / totale") e poi fa il commit. La chiamata senza `stream` resta com'era.
- **Interfaccia:** dopo Delete compare "Deleting… N / total files" con spinner e barra. Mentre gira, Delete e Cancel sono disattivati e il clic fuori dal dialogo non lo chiude. Durante il commit la barra diventa indeterminata ("saving to git history…").
- **Dove vale:** sia il pulsante cestino dell'explorer sia il menu col tasto destro. Per un singolo file mostra lo stato "committing".
- **Alla fine:** il messaggio di successo e l'aggiornamento dell'albero restano quelli di prima. Gli errori compaiono come messaggio, anche se la cartella è stata cancellata ma il push è fallito.
- **Invariato:** la cartella è ancora committata e pushata. Restano le stesse protezioni: cartelle di primo livello, repository annidati e radice non si cancellano.

**Test.**
- Ho eseguito `server/tests/write.test.ts` (37 test) e `web/tests` (49 test + 2 nuovi): tutti passati. Il nuovo test del server cancella 6 file e controlla la sequenza 0/6…6/6, il commit e la cartella sparita.
- Typecheck e build passano.
- Commit `ca488b9` pushato su `main`.

**Restart.** In coda: parte tra 20 secondi quando nessun altro task di Second Brain è in corso.

**Limite.** Se la connessione cade a metà, la UI dice di ricaricare l'albero.

**How to check:** su memory.beedme.online crea una cartella di prova con molti file in `wiki/`. Poi cancellala dal cestino e dal tasto destro: devi vedere il contatore salire, poi il messaggio finale e l'albero aggiornato. `git log -1` nella cartella second-brain deve mostrare `Delete wiki/<cartella>`.

**READY TO SHIP:** repo `second-brain-app`, branch `main`, commit `ca488b9`, pushato sì, build fatta, restart in coda sì. Manca solo la verifica visiva con gli screenshot.
