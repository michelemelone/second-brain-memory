## Request

1. Every app unit (bigmike, gantry, health-server, finance-web, second-brain) gets a start limit (for example `StartLimitIntervalSec=120`, `StartLimitBurst=5`) and a `RestartSec` that cannot spin at 5-second intervals thousands of times. Verified with `systemctl --user show <unit> -p StartLimitIntervalUSec -p StartLimitBurst -p RestartUSec`.
2. When a service reaches the limit it stays failed with an explicit reason visible in `systemctl --user status <unit>` instead of looping. Verified by breaking a test unit on purpose and reading the status.
3. bigMike shows a visible warning when any app service is failed or has restarted N times in M minutes: a banner in the Lab Dashboard and a push notification to the owner phone. Verified on screen and on the phone.
4. The warning appears fast: a service that crash-loops is flagged within 5 minutes. Verified with timestamps from a real simulated crash loop.
5. No false positives: one normal queued restart (as happens on every deploy) never raises the warning. Verified on a normal deploy.
6. The notification says which service, since when, how many restarts and the first error line of its journal, so the owner understands without opening a terminal. Verified in the notification text.
7. Every new string is in English; `tsc` and the tests pass; `npm run build` passes where code changed; committed and pushed; restart queued with `bigmike-restart bigMike --task <KEY>` if bigMike code changed. Verified by the pasted output.
