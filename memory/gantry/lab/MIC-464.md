## Findings (for the owner / follow-up tasks)

- **Global requirements cannot be released by design.** #162 was moved to Global (by an earlier attempt); Global scope has no SDK project. Criterion 6 needs a product decision (an Update Set release path for Global, or re-file #162 in a scoped application whose parity is clean).
- **A same-file overlap is a stop, not a wait that clears.** The release step treats the deploy's "waiting" answer (exit 3) as a failed install: the requirement stays at built with the reason and a Retry, and a Retry fails again while both versions of the file exist. `startBlockersOf` (the file-name overlap ahead of a run) cannot fire in practice, because a branch only changes files once it deployed, i.e. after `built`.
- **Cleanup of a released requirement was broken twice** and is fixed in `ec69d40` (gantry/programs `servicenow_ai/gantry/backend`): (a) `cleanup-source.mjs` was not copied into a workspace's `scripts/`, so every cleanup deploy died with ERR_MODULE_NOT_FOUND; (b) the delete guard blamed ids that main's keys.ts already marks deleted, because a keys merge drops the flags — it now reads them from the base commit's keys.ts too.
- **Lab Management cannot be installed on dev295743** ("Unable to install third party application 'x_snc_lab_man'"), so the proof moved to Country Test, the application with a recent clean deploy.
- **The delete of a released requirement leaves its documentation folder in main's tree**, as uncommitted deletions; the throwaway docs were removed with commits 5cf0f8f and 7972941.
