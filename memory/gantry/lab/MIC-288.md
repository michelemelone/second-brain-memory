## Request

Part of MIC-286. Audit every header control, every control with no label, and every low-contrast text or icon in Gantry. Fix them in dark and light mode (the Select trigger is already fixed in 5a25c44). Keep all UI text in English. Dev only; Gantry Enterprise is not part of this.

## Last report of the agent

I fixed the one real contrast problem I found, but I did not check it by eye. The commit is `6f3e4d8`, pushed to `main`. No headless browser was available, so I have no screenshots. I ran `npm run build`, which passed, and the new rule appears in the built CSS. I ran no unit tests, since the change is CSS only.

**What I checked**
- **Header:** it has a fixed dark navy background with white text, and the instance picker already has the text fix from `5a25c44`. Nothing to change.
- **Form fields:** the input, textarea and select styles I looked at already set `text-fg`. That covers the Setup wizard, Login, Settings, Best Practices, Board, Applications, Agents and the dialogs, in both themes. Nothing to change.
- **Unlabelled controls:** the icon-only buttons I looked at inherit their colour from the page, so they have no contrast problem. I did not inspect every control in the app.
- **Coloured buttons and badges:** white text on the solid status colours is too low-contrast for text.

| Fill | White-text contrast | Where |
|---|---|---|
| danger (dark mode) | about 3.8:1 | confirm/delete buttons, production banner |
| info (dark mode) | about 2.6:1 | Knowledge Base button, doc and best-practice badges |
| warn (dark mode) | about 2.1:1 | doc badge |
| warn (light mode) | about 3.2:1 | doc badge |

Text needs about 4.5:1 to be easy to read.

**Fix:** one CSS rule at the end of `src/index.css` switches the text to dark ink (`#0f172a`) on danger, info and warn fills in dark mode, and on warn fills in light mode. I put it in one rule instead of editing about 20 files. Light-mode danger and info (4.8:1 and above) are unchanged.

**What is left**
- The dark and light screenshots are still missing. MIC-291 (the side-by-side Lab and Gantry comparison) is the natural place to check this change by eye.
- Faint text in places like the placeholders and the small hints is probably fine. The `fg-subtle` text colour (the faint secondary-text token) measures about 5:1 in light mode and a similar value in dark mode, but I did not test every use.
- No server code changed, so no restart is needed. The frontend build is in `dist`.

How to check: open Gantry in dark mode and look at a red "Delete" confirm button, the production banner, or a blue/amber badge in the documentation viewer. The text should be dark and clearly readable.
