## Request

ACCEPTANCE CRITERIA
1. New read-only endpoint GET /backlog/:id/footprint works for a PBI in any state (verified by backend tests: never released, released, partially released with a failed second run).
2. It lists the Fluent source traces: requirement worktree, branch, deployed refs, project files owned by the requirement (verified by test on a fixture repo).
3. It lists the platform records created by the requirement (by keys from its runs), and separately the records only modified, marked 'not touched' (verified by test).
4. It lists leftovers: update set XML, job logs, documentation folder, attachments (verified by test).
5. It reads the data of every run of the requirement, so a first release is found even when the second step failed (verified by test).
6. When something cannot be located it is reported as 'unknown', not guessed (verified by test).
7. Nothing is modified (verified: repo and DB unchanged after the call).

Context: today DELETE /backlog/:id (backend/src/backlog/routes.ts) and the trash button (frontend PbiTab.tsx, canDeletePbi) allow only state Release (introduced by MIC-214, after MIC-206). withdrawRequirement (applications/withdrawRequirement.ts) acts only when a worktree and a deployed ref exist, otherwise returns null and removes nothing. Goal: the owner can delete a PBI in ANY state and everything it left in Fluent source and on the platform is found and removed. Rule agreed with the owner: only records CREATED by the requirement are removed; records it only modified are listed as 'not touched'. Never force or guess: if something cannot be located, say so.
