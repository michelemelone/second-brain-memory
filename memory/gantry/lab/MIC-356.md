## Request

1. Creating a requirement produces exactly one document file, <bundle>/PBI.md, plus state.json: no README.md, no CHANGELOG.md and none of the six folders (business requirements, functional requirements, technical design, test cases, test results, project documents). Verified by creating a requirement in Gantry and listing the bundle folder.
2. PBI.md contains seven sections in this order — 1. Request (verbatim), 2. Acceptance criteria (numbered), 3. Analysis & design, 4. Build log, 5. Verification log, 6. Deployment & rollback, 7. Change log — each labelled with the agent that owns it. Verified by opening the generated file.
3. The Documents tab shows PBI.md and still allows reading and editing it; no entry points to the removed files remain. Verified with screenshots of the Documents tab.
4. Knowledge base generation reads PBI.md of every bundle of the feature (not the six folders) and produces the feature knowledge base with the same coverage as before. Verified by running a generation for one feature and checking the output mentions content from the PBI.md files.
5. A migration script converts every existing bundle (about 56) into a single PBI.md, preserving all the text of the old files (mapped into the seven sections, reference material appended under the matching section), and archives the originals outside the bundle so nothing is lost; the script is idempotent and supports a dry run. Verified with the dry-run report, the before/after file counts, and a second run that changes nothing.
6. Backend tests, frontend tests and both builds pass. Verified by the commands' output.

Context and analysis
Today every requirement is a folder with 8 files in 6 subfolders plus state.json (see requirements/bundleSkeleton.ts, BUNDLE_FOLDERS). A real bundle (vpn-access-request_pbi) is 828 lines: README 43, CHANGELOG 43, project documents 29, business requirements 42, functional requirements 50, test cases 84, test results 234, technical design 303. Description and acceptance criteria are already on the PBI, so business and functional rewrite them; README, CHANGELOG and the state fields repeat what state.json and the screen already say; test cases and test results duplicate the same path. There are 56 bundles in the live instance.

The target: one folder per item (bundle_path stays the anchor used by delivery, artifacts, evidence, chat scope) containing a single PBI.md. The folder-per-item stays; the six subfolders and the two root files go. Level-2 items get their own folder at the same depth under the feature folder; the link to the parent stays in the data (related_to), not on disk.

Migration must not destroy text: each old file's content is carried into PBI.md, and the originals are archived under <documentationRoot>/_legacy/<bundle-name>/ with a manifest. Documentation lives per instance, so the script must walk every instance.

Related tasks: MIC-205 (analysis), MIC-226 (Documents, Artifacts, Evidence tabs), MIC-311 (Documents tab explorer).
