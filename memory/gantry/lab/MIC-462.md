# MIC-462: Gantry: remove the manual Release step: a run goes on to Release by itself, no 'ready to release' banner

- Project: Gantry
- Status: todo
- Priority: high
- Agent: Pegasus

- Updated: 2026-11-25

## Request

ACCEPTANCE CRITERIA
1. A delivery run that passes build, static check, install and live test goes on to Release by itself, in the same run, with no stop at 'Ready to release' and no button to press (backend test on the run phases + one live run on the dev instance with its evidence).
2. The 'N requirement(s) ready to release' banner and its Release button in the Sprint / Backlog and on the application page are removed; the Release notice only shows a real Installing, Failed or Installed state of a release in progress (MIC-441) (frontend test + screenshot on the live page).
3. The batch release logic of MIC-427 stays available as the engine that does the release (dependency order, one build and one install when several requirements finish together), but is started by the run, not by a person; a requirement that depends on an unreleased one waits and is released as soon as the dependency is (backend test).
4. If the automatic release fails, the requirement shows the failure with the reason and a Retry; nothing is left half-installed (test; recheck of a failed read-back never reinstalls, as MIC-440).
5. The state 'Ready to release' disappears from the Delivery Pipeline, the Backlog state badge and the Process.md / agent prompts / in-app help, which describe the new flow (grep of the diff and of the docs for 'ready to release' shows only history/change-log mentions).
6. Requirement #162 (now 'Ready to release', change_pending) moves on to Release by itself after the change, or is shown with the reason it cannot (checked live).
7. Existing requirements already Release/Installed are not touched (list before and after).
8. All UI strings in English; no Italian in the diff (grep). Frontend and backend built and deployed from a clean checkout of the latest commit; the Gantry restart requested (say the commit built).

Context: the owner remembers that the manual release step had been removed ('we do everything now'). The repository history shows no such change: MIC-426, MIC-427, MIC-428, MIC-431 and MIC-432 introduced the stop at 'Ready to release' and the manual batch Release (still live), and MIC-439 to MIC-441 and MIC-458 improved the release. This task reverses that design as the owner asked. Use bigmike-gantry for the live API.
