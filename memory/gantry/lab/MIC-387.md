## Acceptance criteria
1. **No fixed pixel magic numbers: the sidebar geometry is derived from the viewport.** The min width, the max width and the default width of the Gantry sidebar are not hard-coded constants that break as soon as the window size changes: they are computed from the current viewport (a min/max expressed as a share of the window, with sane absolute floors/caps), and the same computation is used when a width is restored from `localStorage`, so a width saved on a large monitor never overflows a small one. Verified: code review of `SidebarResizer.tsx`/`Sidebar.tsx` showing the clamps are viewport-derived (no bare `150`/`560`/`288` driving the layout), plus a live check at several window sizes.
1. **Responsive to page resize.** On a window `resize` the sidebar width is re-clamped to the viewport and the sidebar never overflows the page nor squeezes the content area out; when the window grows back the sidebar returns to its saved width (not to the shrunk value). Verified: in the live Gantry UI, resize the window from wide to 1024, 800 and 390 px and back, checking the sidebar stays inside the viewport, the content keeps usable room, and the saved width is restored — also after a reload.
1. **Double-click shrinks to fit content (snug, not a fixed 288).** Double-clicking the sidebar drag handle when expanded sets the width to fit the sidebar's own content (longest nav label plus its icon and padding, measured from the DOM), clamped by the viewport-derived bounds of criterion 1 — never the current `onChange(DEFAULT_SIDEBAR_WIDTH)` hard reset. Verified: code review of the `onReset` wiring in `Sidebar.tsx` (a `computeSidebarFit`-style measurement) plus a live check: drag the sidebar wide, double-click, and measure that it snaps flush against the labels with no clipped text and no dead whitespace.
1. **Handle styling matches bigMike.** The drag handle uses bigMike's responsive classes `-mx-1.5 w-4 sm:-mx-1 sm:w-2` (wider touch target on phones, tighter on larger screens) instead of Gantry's current `-mx-1 w-2`. Verified: code diff of the `className` in `SidebarResizer.tsx`, plus a live check that the handle is easy to grab at phone width and still hugs the text on desktop.
1. **No regression.** Collapse/expand button and its tooltip, drag-to-resize with the snap to the icon rail, re-expansion, the mobile drawer, the saved width after reload, dark and light mode all keep working, and the sidebar never regresses on tablet widths. Verified: manual check in the live Gantry UI at 1440 / 1024 / 768 / 390 px, plus the existing sidebar tests if the project has any.
1. **Ship.** `npm run build` succeeds, the change is committed and pushed to the remote, and Gantry is restarted safely so the latest code is live. Verified: build output, `git status`/`git log` showing the commit pushed to `origin/main`, and the live page served by the restarted app.
