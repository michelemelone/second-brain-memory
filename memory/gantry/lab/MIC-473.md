## Request

ACCEPTANCE CRITERIA
1. A new Gantry route (for example POST /api/instances/:id/sdk-run) is reachable by an admin session and by the service-account token (MIC-455), through the same policy table as other admin routes; a non-admin gets 403 and no token gets 401 (backend tests).
2. The body names an allowed command and a working folder; the allowed list is fixed in code and holds at least: now-sdk install, now-sdk build, now-sdk init --scopeName <name>, now-sdk --version, and a read-only auth check. Anything else is refused with an English message (test per refused example, including shell metacharacters and a path that escapes the allowed workspace/worktree roots).
3. Gantry runs the command itself with the selected instance's SN_SDK_* variables (the way a deploy does today), never printing or returning the password or token: the output is returned with the login values masked, and the masking is tested with a command that would echo them.
4. The SDK version can be chosen between the pinned one and an isolated folder holding another version (for example 4.14.3 installed under a throwaway directory), without touching the pinned one (test).
5. Only the development instance: a production or UAT instance is refused before anything runs (the existing guard and its test); the instance lease/queue is respected so it never runs next to a deploy on the same instance (test).
6. The call has a timeout (the long install is allowed up to 10 minutes), the process is killed on timeout, and the exit code and the last output lines come back (test).
7. Every call is recorded in the audit log as 'bigMike (service)' (or the admin's name) with the command, folder, instance and exit code, never the secrets (test).
8. bigmike-gantry gets a subcommand (for example 'bigmike-gantry sdk <instance> <folder> -- <command>') that uses the route with the service token; the token and the instance login are never printed or readable by the caller (test of output and logs).
9. Live proof: a read-only 'now-sdk --version' and the auth check run on dev295743 through the helper and answer, with no secret in the output; a refused command and a production attempt are refused (evidence).
10. The agents' instructions (bigMike COMMON_RULES and the Gantry agent notes) mention the helper and that no other way to the instance login is allowed (programs/server built and the restart queued for bigMike if COMMON_RULES changed).
11. All UI/strings in English; tests and builds pass; Gantry built from a clean checkout of the latest commit and its restart requested (commit named).

Context: MIC-470 (spike: Fluent install into Global) is blocked because the SDK needs the instance login, which only Gantry's server holds and no route uses on behalf of an agent. Owner decision 2026-11-25: build the route so agents work with the owner's power through the service token, with the login never leaving Gantry. Related: MIC-455, MIC-456, MIC-457.
