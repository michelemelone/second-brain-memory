## Last report of the agent

MIC-289 is only partly done: the requirements (PBI) list now uses a separate copy of the Lab Tasks table, but 11 other Gantry tables still use the old `DataTable`. I have no screenshots, so none of it has been checked by eye. The change is committed as `fada191` and pushed to `main`.

**What was done**
- **New copy:** it lives in `frontend/src/components/labtable/` with nothing imported from bigMike. It has the toolbar, selection and context menu, and nesting.
- **Toolbar:** the Lab icon buttons: refresh, Columns, Filter (with an active-count badge), Sort, Group and Expand/Collapse all. An hourglass shows while data loads.
- **Selection:** a checkbox per row plus select-all, Cmd/Ctrl-click to add rows, and a bulk action bar. A right-click menu opens at the cursor and keeps the existing selection.
- **Row actions:** open, start delivery, change state, change priority and delete. State and priority changes also apply to several rows at once. Delete stays limited to released items.
- **Nesting:** a follow-up requirement nests under the one it follows when both are in the list.
- **Empty and loading states, row styling:** they follow the Lab, with a selected-row highlight and a loading placeholder.
- **Wiring:** `BacklogTable.tsx` now renders this copy with the existing columns, inline editing and agent picker. `BacklogPage.tsx` passes the refresh action.
- **Tests and build:**
  - `LabTable.test.tsx` (3 tests) covers nesting, selection with the bulk bar, the context menu and the filter.
  - I changed one `BacklogPage.test.tsx` assertion, because the checkbox column shifted the cell index.
  - `tsc --noEmit` and `npm run build` pass.
  - I ran only `LabTable.test.tsx` and `BacklogPage.test.tsx` (40 tests passed) plus `BacklogTableAgent.test.tsx` and `BacklogDelivery.test.tsx` (16 passed). I did not run the full suite.

**What was not done**
- **Other tables not replaced:** the old `DataTable` is still used by Artifacts, Board, Versions, Instances, Live, Best practices and others. I did not remove it, because converting them would exceed this run's budget. I suggest one follow-up task for those.
- **Search:** the existing search box in the backlog toolbar is unchanged and is not inside the new table.
- **Column resizing:** the new table has no column drag-resize.
- **Page-level states:** the page's own "Loading…" and "No requirements yet" messages still show instead of the table's.
- **Sub-tasks:** I used the existing "follow-up of" link as the parent, since the data has no other parent field.

**Chosen:** I kept the page's search where it was, to avoid duplicating a working feature.
