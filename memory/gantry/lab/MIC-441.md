## Request

ACCEPTANCE CRITERIA
1. After the owner presses Release, the green banner "N requirement(s) ready to release" (Backlog and application page) changes by itself to "Installing N requirement(s)…" listing the requirement keys and titles, the elapsed time and a "Show log" link; the Release button is disabled. Verified by a frontend test and a screenshot.
2. Phases are visible in one line: Building, Installing, Activating flows, Checking. Verified by a test of each state.
3. On failure the banner turns red and stays: "Install failed: #<id> — <first line of the real error>", with "Show log" and "Release again". It never disappears by itself. Verified by a test and a screenshot.
4. On success the banner shows "Installed: #<id>" for a few seconds, then disappears; the row state becomes Released and the card moves. Verified by a test.
5. The requirement's card shows "Installing…" while a release runs (not "Ready to release", not an old failure message), and the failure message when it fails.
6. Everything updates live, without reloading the page (same mechanism as MIC-438). Verified by a test that changes the server state and checks the screen within 3 seconds.
7. Only one release at a time per application: pressing Release while one runs is refused with an English message saying why. Verified by a backend test.
8. All texts in English; tests and builds pass; commit, push, queued restart.

CONTEXT: MIC-427 (Release batch), MIC-438 (live page), MIC-440 (read-back fix).
