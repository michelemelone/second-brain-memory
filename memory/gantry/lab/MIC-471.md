# MIC-471: Gantry: deleting a Global-scope requirement also removes what it created on the instance

- Project: Gantry
- Status: todo
- Priority: high
- Agent: Pegasus

- Updated: 2026-11-25

## Request

ACCEPTANCE CRITERIA
1. Root cause written in the task: discardPbiFiles removes the Update Set XML and the logs, and withdrawRequirement acts only on SDK requirements, so deleting a Global requirement leaves the records it wrote directly on the instance. Verified by reading the code and by a live check of a throwaway Global requirement before the fix.
2. The footprint scan (GET /backlog/:id/footprint) of a Global requirement lists the records its Update Set holds (table, sys_id, name) from the exported Global/<id>_*.xml and from the list kept by global-update-set.mjs, separately from records it only modified (marked 'not touched'), and what it could not locate as unknown (backend tests with a fixture Update Set).
3. DELETE of a Global requirement removes from the instance only the records it created that still exist, in dependency order (children before parents, for example columns and rules before a table), through the same audited path as the SDK cleanup, never anything modified-only, never users, roles, preferences, OAuth or update sets themselves (tests for each exclusion).
4. A table created by the requirement is not dropped automatically: it is listed in the 'to check by hand' result with the link to the Artifacts page and its 'Check on instance' (as MIC-466), like for SDK requirements.
5. If any removal fails, the PBI and its Update Set file stay, nothing is half-reported: the error says which record failed and why (test).
6. The delete dialog previews these records for a Global requirement (MIC-453 preview) and states that the instance changes will be removed (frontend test + screenshot).
7. The removal is dev instance only; a production or UAT instance is refused (existing guard test).
8. Live proof with bigmike-gantry --confirm: a throwaway Global requirement that adds a System Property and a business rule is built, then deleted; both records are gone from the instance, a pre-existing record it only touched is still there, and the listing shows nothing left (evidence). All ZZ test data removed.
9. All UI strings in English; no Italian in the diff. Tests and builds pass; deployed from a clean checkout of the latest commit, the Gantry restart requested (commit named).

Context: Global scope today is delivered through an Update Set made directly on the instance (global-update-set.mjs); the Update Set path is kept unless MIC-470 (spike: Fluent install into Global) proves Fluent works. Related: MIC-467, MIC-469, MIC-452, MIC-466, MIC-451 (footprint). Use bigmike-gantry for the live API; never touch production.
