## Last report of the agent

MIC-471 is built, pushed and live. Deleting a Global-scope requirement now removes from the dev instance the records its
Update Set created, and leaves everything it only modified.

**Root cause (criterion 1).** `discardPbiFiles` removes only the exported `Global/<id>_*.xml` and the job logs, and
`withdrawRequirement` builds its work from the footprint's `platform.created`, which comes from the Fluent keys files in
git. A Global-scope requirement has no Fluent keys at all (it is delivered straight on the instance), so `created` was
empty, no cleanup ran, and the records it wrote stayed on the instance. Seen live before the fix: #162's footprint listed
no record at all while its Update Set held one business rule, and the delete of a Global PBI left its records behind.

**What changed.** The footprint reads the exported Update Set and the delivery log `global-update-set.mjs` keeps
(`<workspace>/.gantry/global/<id>.json`): each entry gives table, sys_id, name, and the record's own `sys_created_on`,
which is compared with the moment the delivery started — older means "modified only", never removed. `DELETE` then runs
`scripts/global-cleanup.mjs` with the records it created, children first (choices, columns, labels, list/form parts, other
records, and a table last of all), on the development instance only, appending every removal to the same audit log. A
table, and the columns/labels/choices that belong to a table the requirement itself created, are not dropped: they go to
the "to check by hand" list, like the SDK path (MIC-466). A column created on a table the requirement did not create is
removed with the rest.

**Two choices worth knowing**
- A column, label or choice that belongs to a table the requirement created stays with that table (the table is never
  dropped automatically), so the owner checks them together by hand. One that belongs to a table the requirement did not
  create is removed.
- The Update Set record itself on the instance is never removed by the delete (criterion 3); it is cleaned up by hand
  (`x_zz`-style), as it was for the probe.
