**MIC-471 is built, pushed and live.** Deleting a Global-scope requirement now removes from the dev instance the records its Update Set created, and leaves what it only modified.

**Root cause (criterion 1).** `discardPbiFiles` removes only `Global/<id>_*.xml` and the job logs, and `withdrawRequirement` works from `platform.created`, which comes from the Fluent keys files in git. A Global requirement has no Fluent keys at all, so `created` was empty, no cleanup ran, and its records stayed. Seen before the fix: #162's footprint listed no record while its Update Set held a business rule.

**What changed**
- `src/backlog/globalUpdateSet.ts` (new): reads `Global/<id>_*.xml` (payload escaped or CDATA) and the log `global-update-set.mjs` keeps (`<workspace>/.gantry/global/<id>.json`): table, sys_id, name, and the record's own `sys_created_on`.
- `src/backlog/footprint.ts`: `platform.global` in `GET /backlog/:id/footprint`; a record is "created" when its creation time is not before the delivery started, "not touched" when older, `unknown` when the export or the log cannot tell.
- `src/applications/globalCleanup.ts` (new): dependency order (choice → column → label → list/form parts → other records → table last), protected tables (users, roles, preferences, OAuth, update sets, scopes) and the keep rule for tables.
- `scripts/global-cleanup.mjs` (new): deletes only those records, GET then DELETE, appends every removal to `servicenow_dev/.gantry/global/audit.log`, refuses a protected table or a table, stops on the first failure naming the record and the reason.
- `withdrawRequirement` runs it *before* any local removal, only on the development instance (`assertDevelopmentInstance`), so a failure keeps the PBI, its bundle and its Update Set file.
- Delete dialog (`ConfirmDeleteDialog.tsx`): previews the Global records with created / not touched / kept and says the records it created are removed from the instance.
