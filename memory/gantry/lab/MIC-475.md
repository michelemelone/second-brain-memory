## Request

1. Root cause written in the task, with the live evidence of requirement #177 (Global): its Update Set file Global/177_country-test-audit.xml holds one entry named sys_ui_form_sections_d0c4fb74c334d310147bd71d050131d2 whose record_update root is the container element <sys_ui_form_sections>; the real record is the nested <sys_ui_form> with sys_id d0c4fb74c334d310147bd71d050131d2. The extraction of the Update Set records takes the container's element name as the table and the nested record's sys_id, so Check on instance reads sys_ui_form_sections/d0c4fb74... on dev295743, the instance answers 400, and the row is reported "unreadable" instead of exists. Evidence: POST /api/artifacts/check with the row of #177 returns {"status":"unreadable","detail":"sys_ui_form_sections/d0c4fb74c334d310147bd71d050131d2: dev295743 answered 400"} (verified live on 2026-11-25); the XML line shows the structure (verified with grep).
2. The record extraction takes table and sys_id from the element that actually carries the record's sys_id (here <sys_ui_form>), never a container element's name; a backend test with this exact payload asserts table=sys_ui_form and sys_id=d0c4fb74c334d310147bd71d050131d2 (test file named in the report).
3. Live proof: POST /api/artifacts/check on the row of #177 (Global/177_country-test-audit.xml) after the fix returns exists, partial or missing with a readable detail and no "unreadable" for that row (command and full JSON in the task).
4. The other Global rows keep their current results: #162 still "All 1 record of the Update Set are on the instance", #176 still "None of the 7 records of the Update Set is on the instance" (commands and JSON in the task).
5. The check never reports a table the payload does not really hold; a container with no sys_id of its own is skipped when it holds no record (test).
6. All strings in English, no Italian in the diff; backend tests and build pass; built from a clean checkout of the latest origin/main and deployed to the live Gantry (say the commit built and that the restart was queued).
