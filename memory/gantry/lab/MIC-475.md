## MIC-475 — Check on instance misread a form's record — done and live

**Root cause (criterion 1).** In `src/artifacts/extractRecordRef.ts`, `extractAllRecordRefs()` read the table and sys_id from the `sys_update_xml` entry's `<name>` (`sys_ui_form_sections_d0c4fb74c334d310147bd71d050131d2`) whenever the name matched `<table>_<32-hex>`, and only looked at the payload otherwise. For a form the platform names the entry after the container element, while the payload's real record is the nested `<sys_ui_form>`: `Global/177_country-test-audit.xml`, entry 467, is `<record_update><sys_ui_form_sections form_id="d0c4fb74…"><sys_ui_form action="INSERT_OR_UPDATE"><sys_id>d0c4fb74c334d310147bd71d050131d2</sys_id>…` — the container carries no sys_id of its own. So the check asked the instance for `sys_ui_form_sections/d0c4fb74…`, which is not a table, and dev295743 answered 400 → `{"status":"unreadable",…}`. It also silently skipped 6 other real records of that file (`sys_choice_set` + 5 `sys_documentation`): their payloads carry no `table=` attribute on `<record_update>` and their names have no 32-hex suffix, so neither old path matched them.

**The fix (57d048f).** `recordElements()` in `src/applications/xmlBlocks.ts` returns, in document order, every element that carries a `sys_id` of its own — a container holding a record but having no sys_id is never one. `extractRecordRef()` and `extractAllRecordRefs()` now read the CDATA payload first (first element carrying the sys_id); the entry's name is used only when the entry has no CDATA payload (as in #162, whose payload is escaped text). One entry still yields at most one record, so no other row changes count.
