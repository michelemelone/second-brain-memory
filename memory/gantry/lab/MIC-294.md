## Request

Problem: in Gantry the left sidebar can only be opened or closed with the toggle button. It cannot be widened by dragging. Michele has asked for this several times: the Gantry sidebar must behave exactly like the bigMike sidebar (see MIC-277, MIC-286, MIC-291).

What to do:
1. Read how the bigMike sidebar works: the drag handle on its right edge, the min and max width, how the width is saved, and the snap behaviour. When you drag below the minimum width, the sidebar snaps to the collapsed rail anchored on the left. When you drag back out, it expands again.
2. Copy that behaviour into Gantry. Reuse the same logic and CSS, not a loose imitation. Keep the collapse/expand button and its tooltip working. Keep the narrow-screen (phone and Galaxy Z Fold) behaviour working.
3. Check that the Gantry sidebar behaves like the bigMike one in both dark and light mode. Check the hover and cursor on the handle, the drag, the snap to the rail, the re-expansion, and the saved width after a reload.
4. Take real before and after screenshots of bigMike and Gantry side by side, and attach them. Done means the behaviour matches in practice, not just in the code. Add a test if the project has a pattern for it.
5. Build, commit and push. Restart Gantry safely so the latest code is live.

Keep all existing Gantry sidebar content, labels and links unchanged. Do not touch Gantry Enterprise. Write all code and comments in English.

## Last report of the agent

The Gantry sidebar can now be dragged to resize, but I took no before/after screenshots and haven't looked at it in dark or light mode. I couldn't take real screenshots because both apps ask for a login, so the cursor, hover and saved-width-after-reload checks are not done.

The commit is `0873262`, pushed to `main`. `npm run build` and `npx tsc --noEmit` passed. The sidebar test file passes (2 tests), including a new drag test.

**What changed**
- **Handle:** I copied bigMike's `SidebarResizer.tsx` logic into Gantry unchanged: min 150, max 560, default 288.
- **Snap:** dragging below 150 snaps to the 64px rail, and dragging back out re-expands it.
- **Mouse and touch:** drag works with mouse and touch, and the arrow keys and double-click also resize it.
- **Colours:** only the handle colours changed. The line uses `gantry-border` and turns the `violet` token on hover, focus and drag. That token has both dark and light values.
- **Width saved:** the existing `gantry-sidebar-width` key is reused, and the rail state still uses `gantry-sidebar-collapsed`.
- **Transition:** the width transition is switched off while dragging so the sidebar follows the cursor.
- **Kept as is:** the collapse/expand button, its tooltip and all sidebar labels and links.
- **Old handle:** I removed it. It was hidden when the sidebar was a rail, so you couldn't drag back out of it.

**Not done**
- **Narrow screens:** Gantry's sidebar has no special phone or Galaxy Z Fold layout, so I added none. The handle is always shown.
- **Existing saved widths:** a saved width under 150 would be clamped up to 150.

The Gantry restart is queued and runs when no other Gantry task is in progress.
