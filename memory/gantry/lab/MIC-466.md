# MIC-466: Gantry Artifacts page: Check on instance (exists / missing), and the delete hands over what is left to check by hand

- Project: Gantry
- Status: todo
- Priority: high
- Agent: Pegasus

- Updated: 2026-11-25

## Request

ACCEPTANCE CRITERIA
1. The Artifacts page (frontend ArtifactsPage.tsx, backend artifacts/routes.ts) has a 'Check on instance' button in its toolbar; it acts on the selected rows, or on every filtered row when none is selected, and never runs on page load (frontend test).
2. A new read-only endpoint (for example POST /artifacts/check) reads each row's record on the row's own instance by table and sys_id, reusing artifacts/instanceRecords.ts and serviceNowClient (reads in chunks, a few at a time, with a timeout), and returns per row: exists, missing, not installed yet (no sys_id), or not readable with the reason, plus the instance's last update date (backend tests with a fake instance for each of the four outcomes; no write call exists on the path).
3. The table shows a column 'On instance' with that result and the date, and a link per row that opens the record on the instance (screenshot, dark and light).
4. A filter 'On instance: all / existing / missing / not checked' narrows the rows; rows not yet checked are shown as not checked (test).
5. Custom tables: the check reads the table in the dictionary (sys_db_object) and also its dictionary rows, so a table removed only in part is shown as 'partly there' with the detail, not as missing (test with a fake instance).
6. The check is refused with an English message for a production instance, and a row of an instance the user may not see is ignored (backend tests; same scope rules as GET /artifacts).
7. The PBI's Artifacts tab (ArtifactsTab.tsx) offers the same button for the rows of that requirement, using the same component, not a copy (test).
8. Delete (DELETE /backlog/:id, ConfirmDeleteDialog) : when it ends, the result lists what the cleanup deploy could not remove (for example tables and their dictionary rows) with the reason, saves that list in the history, and offers a link that opens the Artifacts page filtered on the deleted requirement with the check already run (test + a live run).
9. Live proof on the dev instance with bigmike-gantry: a throwaway requirement that creates a table is released, then deleted; the result lists the table; the Artifacts check shows it as existing; after the table is removed by hand on the instance, the check shows it as missing. The throwaway leaves no other trace (evidence in the task). If the owner has not yet removed the three old ZZ tables (x_608645_country_t_zz_del_one, _zz_e2e_note, _zz_e2e_memo), the check lists them but the task never deletes them.
10. All UI strings in English; no Italian in the diff (grep). Existing tests updated and pass.
11. Built from a clean checkout of the latest commit and deployed; the Gantry restart requested for the server change (say the commit built).

Context: owner decision 2026-11-25. Tables created by a requirement are not dropped by the cleanup deploy; the owner removes them by hand and wants a button that checks, from the Artifacts table, what exists on the instance. Never delete tables automatically. Related: MIC-451 (footprint), MIC-452, MIC-453, MIC-458. Depends on MIC-465 (the end-to-end flow tasks run first). Use bigmike-gantry for the live API.
