## Request

ACCEPTANCE CRITERIA
1. A requirement that was never delivered cannot start its first run until it has been validated with AI: Start run is disabled in the table and on the requirement page with an English tooltip, and the API refuses a direct start with a 409 and a clear English error. Verified by an API call, a test and screenshots.
2. Any edit of title, description or acceptance criteria after a validation re-arms the block until the new content is validated, exactly like MIC-416 does for a released requirement; the validated revision is stored on the server and survives a reload. Verified by validating, editing and reading the button again.
3. The validating agent sees the diff of what changed (previous and new text per field), as in MIC-416, also before the first delivery once a first validation exists. Verified by a backend test on the prompt.
4. Each state has one English line saying what to do next and no state is a dead end: edited and not validated, validation running, changes proposed, validated, run enabled. Verified by walking the states on screen.
5. The banner of MIC-416 for a released requirement keeps working unchanged. Verified by its existing tests.
6. Backend and frontend tests and both builds pass; committed, pushed, restart queued.

CONTEXT (owner decisions, 2026-11-21). New Gantry delivery model: the owner defines and validates requirements, a run implements and compiles them (it stops at "Ready to release", task MIC-426), and the owner decides when to install a whole batch. The live test is done by the owner by hand on the platform after installation, so no live verification is automated and the tester is not started at release. EVERY user-facing string (buttons, banners, tooltips, errors, empty states, hints) is in English only, in line with the existing Gantry rules; search the diff for Italian words. Keep the Lab-copy look (MIC-286, MIC-329): dark and light, desktop and phone. Related done tasks to respect: MIC-363, MIC-361, MIC-362, MIC-415, MIC-416. Repo: gantry/programs. The Gantry brief second-brain/memory/gantry/BRIEF.md is missing; report it, do not invent it. Finish with builds, tests, commit, push and the Gantry restart queued (bigmike-restart Gantry).
