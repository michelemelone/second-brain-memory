## Request

1. The startup guard that today throws when there is an open worktree AND the legacy "documentation/projects requirements" folder is not empty no longer ends in `process.exit(1)`: it logs the reason, keeps the service up with the documentation where it is, and retries the migration on the next start or on a later attempt. Verified by reproducing the exact state (one entry in `.worktrees` + non-empty legacy folder) and starting the service: Gantry answers.
2. The exact condition of tonight is covered by an automated test (a fixture repo with an open worktree and a non-empty legacy docs folder) that fails if `process.exit` is called or the server does not listen. Verified by the test output.
3. The documentation migration is idempotent: running it twice moves nothing the second time and never recreates the legacy folder (part of `53493db` already does this). Verified by a test that runs it twice.
4. No startup path recreates `documentation/projects requirements` after the split into instances. Verified by a test and by checking the folder after a restart.
5. When a startup problem is real and unavoidable, the log says in one line what is wrong and what to do, and it is logged once, not thousands of times. Verified in the journal of a simulated failure.
6. The dirty file `build_agent/skills/servicenow-development/lessons.md` present in the repository is committed with its task or reverted, so `git status --porcelain` is empty. Verified by the pasted output.
7. Every new string is in English; `tsc` and the Gantry tests pass; the change is committed and pushed to `origin/main`; the restart is queued with `bigmike-restart Gantry --task <KEY>`. Verified by the pasted output and by `git rev-list --count @{u}..HEAD` = 0.

Analysis
- Root cause of the 11-hour outage (19/11 20:34:46 → 20/11 07:50): the new build ran the migration "documentation into the instance folder" and stopped with `exit 1` because an open worktree existed (`bug-2-audit-services-link-field-must-be-html-...`) and the old folder was not empty. systemd restarted it every 5 seconds: 7,086 restart counter, about 35,720 journal lines, Gantry unreachable all night.
- The guard is still in `programs/servicenow_ai/gantry/backend/src/server.ts` around lines 287-300: `if (open.length > 0 && hasLegacyDocs) throw new Error(...)` inside a `try` whose `catch` calls `process.exit(1)`. A condition that depends on the state of the repository can therefore never self-heal and becomes an infinite crash loop.
- Commit `53493db` ("do not recreate legacy shared docs folder after instance split or block startup on empty legacy dir") removed one of the causes (the template recreating the folder) but not the fatal exit.
- Related: MIC-372 (crash-loop protection and alerting at the systemd level).
- Needs `npm run build`, commit + push, restart queued with `bigmike-restart Gantry --task <KEY>`.
