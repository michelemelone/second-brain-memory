### 2. Validation Round Counter Bug Root Cause & Fix
- **Root Cause on Requirement #169**:
  In `servicenow_ai/gantry/backend/src/backlog/routes.ts` (`PUT /backlog/:id`), the handler previously included:
  ```ts
  else if (store.resetValidationRounds && before.validated_revision !== null && revisionOf(before) === before.validated_revision && revisionOf(updated) !== before.validated_revision && (updated.validation_rounds ?? 0) > 0) {
    updated = (await store.resetValidationRounds(id)) ?? updated;
  }
  ```
  Every time text was adjusted or applied by hand, `resetValidationRounds` reset `validation_rounds` back to `0`. The subsequent validation round saw `0` rounds and incremented it to `1` (`(prev.validation_rounds ?? 0) + 1 = 1`). Consequently, all 5 validation turns on #169 remained stuck at "round 1", preventing the counter from ever reaching 3 and hiding "Accept as is, start anyway".
- **Fix**: Removed the hand-edit reset. Validation rounds increment continuously across validations and hand edits during an iteration, resetting only when starting a new iteration cycle after a release (`before.pending_run !== true`). From round 3 onwards, "Accept as is, start anyway" is always available.
