## Request

1. On the requirement detail page (the page in the attached screenshot) the three columns fill the full available width, with no dead gap at the right and no horizontal scrollbar, at 1920×1080 and 1280×800 — verified by screenshots and DevTools measurements showing the column widths sum to the content width at both sizes.
2. The Conversation (chat) column never exceeds 25% of the page content width, at default layout and with its splitter dragged to the maximum — verified by dragging the handle to the stop and screenshotting the measured percentage (≤ 25.0% at 1920 and 1280 px).
3. The first column (requirement tabs requirement/bug/API task, description, acceptance criteria, attachments) keeps its space: at default layout it is at least 40% of the page width and it never drops below a readable width at minimum (no one-word-per-line wrapping, no inner horizontal scrollbar) — verified with a long requirement open, screenshots plus measurements at both viewport sizes.
4. The last column (internal tabs PBI, Live, Open Questions, Documents, Artifacts, Evidence, Retrospective and the Properties classification/planning/assignment panels) takes the remaining space and its content expands to the full column width, with fields laid out in two columns and no empty white bands or extra wrapping — verified by a screenshot per tab showing content matching the column width.
5. The layout holds after a page reload, after switching each of the seven tabs and after resizing the columns — verified by repeating the same measurements after reload and on every tab, with no layout jump.
6. If the same splitter component is used on another screen, it applies the same 25% cap there; if it is used only here, say so explicitly in the task — verified by opening the other screen with that component and repeating the drag-to-maximum measurement.
7. The change touches only the column widths: cards, buttons, tab bar, badges and the Properties content stay visually identical — verified by a before/after side-by-side screenshot.

What to do: rebalance the splitter minimum/maximum values and the flex/grid basis of the three columns so the page fills its width, the last column's internal tabs expand and the chat never passes 25%. What to keep: the current tab set and order, the Properties cards, the splitter usability and every other screen's behaviour.
